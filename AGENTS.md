# When Talking
- Be concise and direct with your responses

# When Coding
- Never write unit tests unless specifically asked
- Never leave comments in code unless specifically asked
- Never use schema or version numbers in data objects unless specifically asked
- Never add backwards compatibility schemes for existing data types unless specifically asked
- Never edit documentation or README files unless specifically asked
- Never add "provenance", "sources", "reasoning" or other metadata when writing financial metris unless specifically asked
- Prefer concise and functional coding patterns
- Avoid many one off, small variables; instead prefer to nest expressions
